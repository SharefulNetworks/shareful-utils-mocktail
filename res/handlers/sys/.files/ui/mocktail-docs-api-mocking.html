Intro to API Mocking.

Overview

Mocktail Server is a purpose built server for mocking APIs. (static and dynamic web serving are really just ancillary features) It is designed to be simple to set up and use, allowing developers to quickly set up mock APIs for testing and development purposes. There are broadly two ways to mock APIs on Mocktail Server:

  1. Mocking via Web UI. Mocktail Server provides a simple and intuitive interface that allows users to create and manage mock APIs without writing any code. This is the fastest way to get started with API mocking on Mocktail Server.

  2. Mocking via Raw JSON. This method allows users to define mock APIs, directly, using JSON files, providing more flexibility and control over the mocking process. This is ideal where there is a requirement to programmatically generate, manage and update mock APIs, perhaps from a parent application.
Regardless of the API mocking method, one elects to use, Mocktail Server provides a robust and reliable platform for mocking APIs, making it an invaluable tool for developers and testers alike. Next we'll take a brief look at the structure of a Mock API on Mocktail Server, before we dive into the details of each of the two API mocking methods.

Structure of a Mock API

Regardless of whether you choose to mock APIs via the Web UI or via Raw JSON, the structure of a Mock API on Mocktail Server is the same. A Mock API consists of two hierarchically nested components:

  1. Mock API Collection. This is the top level component of a Mock API. It defines the overall structure and behavior of the Mock API, including its name, description, unique ID and any endpoints it exposes.

  2. Mock API Collection Endpoint. This is the second level component of a Mock API. It defines a specific endpoint within the Mock API, including its path, HTTP method, request parameters, and response data. A single Mock API Collection can and often will contain multiple Mock API Collection Endpoints.

In the next section, we'll take a look at how to mock APIs via the Web UI. This is the fastest way to get started with API mocking on Mocktail Server as there is no requirement to write any code aside from the actual (JSON based) mock API response data.

Accesing the API Mocking Web App

To access the API Mocking Web App, simply spin up an instance of the server as described in the Installation section of the Getting Started guide. Once the server is running, navigate to the following URL in your web browser: http://localhost:3000/. This will open the Mocktail Server Start Page, as shown below:

Next hover over the API Mocking card. This will cause the card to rotate and reveal the API Mocking Console Button, as shown below, clicking this will take you to the API Mocking Web App where you can create and manage your mock APIs.

Note: you must be logged in as an admin user to access the API Mocking Web App. If you are not logged in, you will be prompted to log in before you are able to proceed to the API Mocking Web App. For more information on how to login or create an admin account where one does not already exist, please refer to the Getting Started guide.

API Mocking via Raw JSON.

Overview

Raw JSON mocking lets you define mock API collections directly in JSON files. This is the best fit when you want to generate, version, or update mock APIs from another tool or application.

Accessing the Raw JSON Files

Mocktail stores raw mock API definitions as JSON collections. You can use the template collection as a starting point and copy it into the mock API location used by your setup. 

{
  "name": "Example Mock API Collection",
  "description": "A simple mock API defined in raw JSON",
  "endpoints": [
    {
      "path": "/api/status",
      "method": "GET",
      "response": {
        "status": 200,
        "body": {
          "status": "ok"
        }
      }
    }
  ]
}

Creating a New Mock API Collection

Start with a collection object, then add one or more endpoint definitions beneath it. The structure is the same whether you are hand-editing JSON or generating it programmatically.

If you prefer a guided workflow, the Web UI is the faster place to begin. Raw JSON is more flexible once you already know the shape of the mock you want to maintain.
